# Отчет по 3 этапу — Web-интерфейс и обработка запросов

## 1. Общая характеристика проекта

Проект представляет собой Spring Boot web-приложение интернет-магазина бытовой техники. В приложении используются:

- **Spring MVC** для обработки HTTP-запросов;
- **Spring Security** для аутентификации и разграничения доступа по ролям;
- **JSP** для серверного рендеринга страниц;
- **Hibernate / JPA** для работы с данными;
- **PostgreSQL** в качестве СУБД;
- **Gradle** для сборки Java-кода;
- **Ant** для подготовки базы данных, локального развертывания и оркестрации тестов;
- **Selenium WebDriver + TestNG** для системного тестирования.

Приложение поддерживает четыре уровня доступа:

- гость;
- пользователь;
- менеджер;
- администратор.

## 2. Структура итогового проекта

### 2.1 Основной исходный код

`src/main/java/javaprac/`

- `JavapracApplication.java` — точка входа в приложение.
- `config/`
  - `JpaEntityManagerConfig.java` — конфигурация общего bean'а `EntityManager`.
- `controller/`
  - `HomeController.java` — домашние страницы.
  - `AuthController.java` — вход и регистрация.
  - `ProductController.java` — каталог и карточки товаров.
  - `CartController.java` — корзина и оформление заказа.
  - `ProfileController.java` — профиль пользователя и смена пароля.
  - `AdminAccountController.java` — профиль администратора.
  - `UserAdminController.java` — управление пользователями со стороны администратора.
  - `StaffCatalogController.java` — типы товаров, производители и характеристики типов.
  - `StaffProductController.java` — управление товарами.
  - `StaffOrderController.java` — управление заказами со стороны персонала.
  - `NavControllerAdvice.java` — общие данные навигации для представлений.
- `service/`
  - бизнес-логика аутентификации, пользователей, каталога, корзины, заказов, навигации и staff/admin-сценариев.
- `dao/`
  - DAO-классы на Hibernate для пользователей, товаров, типов товаров, производителей, характеристик, заказов и позиций заказа.
- `model/`
  - доменные сущности: `AppUser`, `Product`, `ProductType`, `Manufacturer`, `OrderEntity`, `OrderItem`, `ProductAttributeValue` и др.
- `security/`
  - `SecurityConfig.java` — конфигурация Spring Security;
  - `DbUserDetailsService.java` — аутентификация пользователей из БД;
  - `DisabledUserLogoutFilter.java` — завершение сессии отключенных пользователей;
  - `AdminBootstrap.java` — создание стартовой учетной записи администратора.

### 2.2 Ресурсы и web-представления

`src/main/resources/`

- `application.properties` — параметры datasource, настройки JSP prefix/suffix, учетные данные bootstrap-администратора.
- `hibernate.cfg.xml` — конфигурация Hibernate.

`src/main/webapp/WEB-INF/jsp/`

Основные JSP-страницы:

- публичные страницы: `home.jsp`, `products.jsp`, `product.jsp`, `login.jsp`, `register.jsp`;
- пользовательские страницы: `cart.jsp`, `my_orders.jsp`, `profile.jsp`;
- страницы администратора: `home_admin.jsp`, `users_admin.jsp`, `user_create_admin.jsp`, `user_form_admin.jsp`, `admin_me.jsp`;
- страницы персонала: `catalog_staff.jsp`, `product_types_staff.jsp`, `product_type_form_staff.jsp`, `manufacturers_staff.jsp`, `manufacturer_form_staff.jsp`, `type_attributes_staff.jsp`, `type_attribute_form_staff.jsp`, `products_staff.jsp`, `product_form_staff.jsp`, `orders_staff.jsp`, `order_details_staff.jsp`.

### 2.3 База данных и файлы сборки

- `db/create.sql` — создание схемы базы данных;
- `db/init.sql` — начальные данные;
- `db/cleanup.sql` — очистка схемы;
- `build.gradle.kts` — конфигурация Gradle для сборки и тестов;
- `build.xml` — Ant-задачи для подготовки БД, локального развертывания и тестирования;
- `build.properties` — параметры подключения к БД для Ant.

### 2.4 Тесты

`src/test/java/javaprac/`

- `dao/` — DAO-тесты;
- `system/` — Selenium-системные тесты:
  - `BaseSystemTest.java` — общая Selenium-инфраструктура;
  - `PublicAuthCartSystemTest.java` — публичные и пользовательские сценарии;
  - `AdminAndStaffSystemTest.java` — сценарии администратора и персонала.

## 3. Web-интерфейс и обработка запросов

### 3.1 Публичный и пользовательский интерфейс

Реализованы следующие пользовательские сценарии:

- просмотр главной страницы;
- просмотр каталога с фильтрами;
- открытие карточек товаров;
- регистрация и вход в систему;
- переход на защищенные страницы после аутентификации через параметр `continue`;
- добавление товара в корзину;
- изменение количества товара в корзине;
- удаление товара из корзины;
- оформление заказа;
- просмотр и отмена заказа;
- редактирование профиля;
- смена пароля.

### 3.2 Интерфейс персонала

Реализованы следующие staff-сценарии:

- создание типов товаров;
- создание производителей;
- создание характеристик типов товаров;
- создание товаров;
- просмотр списка заказов;
- открытие деталей заказа;
- изменение статуса заказа;
- удаление заказов только в допустимых состояниях.

### 3.3 Интерфейс администратора

Реализованы следующие административные сценарии:

- просмотр домашней страницы администратора;
- создание пользователей;
- редактирование профиля пользователя;
- изменение учетных данных пользователя;
- включение и отключение пользователей.

## 4. Конфигурация

### 4.1 Конфигурация Spring

В проекте присутствует требуемая конфигурация Spring-приложения:

- `SecurityConfig.java` определяет:
  - правила доступа для публичных, пользовательских, manager- и admin-маршрутов;
  - кастомную страницу логина;
  - обработчик успешной аутентификации;
  - кастомный редирект при ошибке входа;
  - поведение logout.
- `JpaEntityManagerConfig.java` определяет общий JPA bean `EntityManager`.

### 4.2 Конфигурация основного сервлета / web-конфигурация

Приложение настроено как Spring Boot MVC-приложение с поддержкой JSP. Основная web-конфигурация задается в:

- `JavapracApplication.java`;
- `application.properties`:
  - `spring.mvc.view.prefix=/WEB-INF/jsp/`
  - `spring.mvc.view.suffix=.jsp`

Эта конфигурация обеспечивает обработку MVC-маршрутов и отображение JSP-представлений.

## 5. Сценарии системного тестирования

Системные тесты реализованы с использованием **Selenium WebDriver** и **TestNG**. Они покрывают основные пользовательские сценарии и ключевые ветки валидации и ограничений.

### 5.1 Публичные и пользовательские сценарии (`PublicAuthCartSystemTest`)

1. **Гость может просматривать каталог и открывать карточку товара**
   - открыть главную страницу;
   - перейти в каталог;
   - применить фильтры по типу и производителю;
   - открыть карточку товара.

2. **Защищенная страница перенаправляет гостя на вход**
   - открыть `/cart` без аутентификации;
   - проверить редирект на `/login`.

3. **Вход с параметром `continue` перенаправляет в корзину**
   - зарегистрировать пользователя;
   - выйти из системы;
   - открыть `/login?continue=/cart`;
   - выполнить вход;
   - проверить переход на `/cart`.

4. **Регистрация проходит успешно, повторный email отклоняется**
   - зарегистрировать нового пользователя;
   - проверить переход в каталог;
   - повторно попытаться зарегистрировать тот же email;
   - проверить сообщение о занятом email.

5. **Некорректный вход показывает сообщение об ошибке**
   - попытаться войти с несуществующими учетными данными;
   - проверить сообщение об ошибке.

6. **Пользователь может изменить количество товара в корзине и удалить его**
   - добавить товар в корзину;
   - изменить количество;
   - удалить товар;
   - проверить сообщения об успехе и пустое состояние корзины.

7. **Пользователь может оформить и отменить заказ**
   - добавить товар в корзину;
   - указать данные доставки;
   - оформить заказ;
   - отменить заказ;
   - проверить сообщение об успехе.

8. **Пользователь может изменить профиль и пароль**
   - изменить данные профиля;
   - сохранить профиль;
   - сменить пароль;
   - войти с новым паролем.

### 5.2 Сценарии администратора и персонала (`AdminAndStaffSystemTest`)

1. **Администратор может создать пользователя, а повторный email отклоняется**
   - создать учетную запись менеджера;
   - попытаться создать еще одного пользователя с тем же email;
   - проверить сообщение валидации.

2. **Администратор может отключить пользователя, после чего вход блокируется**
   - создать пользователя;
   - отключить пользователя;
   - проверить, что вход больше не проходит.

3. **Администратор может редактировать профиль пользователя**
   - создать пользователя;
   - изменить ФИО, телефон и адрес;
   - проверить обновленные данные.

4. **Администратор может изменить учетные данные пользователя**
   - создать пользователя;
   - изменить email и пароль;
   - проверить вход с новыми учетными данными.

5. **Менеджер может создать тип товара, а дубликат отклоняется**
   - создать новый тип;
   - повторно попытаться создать тот же тип;
   - проверить сообщение о дубликате.

6. **Менеджер не может удалить тип товара, уже связанный с товарами**
   - попытаться удалить тип, для которого есть товары;
   - проверить сообщение об ограничении.

7. **Менеджер может создать производителя, характеристику типа и товар**
   - создать тип товара;
   - создать производителя;
   - создать характеристику типа;
   - проверить ошибку при добавлении дублирующейся характеристики;
   - создать товар со значением характеристики.

8. **Менеджер может провести заказ до статуса delivered и удалить его**
   - пользователь оформляет заказ;
   - менеджер меняет статус с `processing` на `packed`;
   - затем с `packed` на `delivered`;
   - после этого удаляет заказ.

9. **Менеджер получает ошибку при недопустимом переходе статуса**
   - попытаться перевести заказ напрямую из `processing` в `delivered`;
   - проверить сообщение валидации.

10. **Менеджер не может удалить заказ в статусе processing**
    - пользователь оформляет заказ;
    - менеджер пытается удалить его, пока заказ находится в статусе `processing`;
    - проверить сообщение об ограничении.

## 6. Сборка, локальное развертывание и тестирование

### 6.1 Назначение `build.xml`

`build.xml` оркестрирует:

- подготовку базы данных;
- запуск DAO/unit-тестов;
- локальную сборку и развертывание приложения;
- запуск Selenium-системных тестов.

Файл содержит отдельную задачу для **полной сборки и развертывания**:

- `full-build` — выполняет полную локальную сборку и развертывание приложения.

### 6.2 Основные Ant-target'ы

- `db-create` — выполнить `db/create.sql`;
- `db-init` — выполнить `db/init.sql`;
- `db-clean` — выполнить `db/cleanup.sql`;
- `db-reset` — очистка + создание + инициализация;
- `test-db-reset` — очистка + создание для DAO-тестов;
- `test` — DAO/unit-тесты на пустой схеме;
- `test-report` — DAO/unit-тесты + JaCoCo-report;
- `deploy-local` — reset seeded БД, сборка JAR и локальный запуск приложения;
- `undeploy-local` — остановка локального приложения;
- `system-test` — запуск Selenium-системных тестов против локального приложения;
- `system-test-stop` — запуск Selenium-системных тестов и последующая остановка локального приложения;
- `full-build` — полная локальная сборка и развертывание.

### 6.3 Инструкция по полной сборке и развертыванию

#### Предварительные условия

В системе должны быть установлены и доступны:

- Java;
- поддержка Gradle wrapper (`./gradlew`);
- Ant;
- клиентские утилиты PostgreSQL:
  - `psql`
  - `pg_dump`

Файл `build.properties` должен содержать корректные параметры подключения к БД:

- `db.host`
- `db.port`
- `db.name`
- `db.user`
- `db.password`

#### Пошаговая инструкция

1. Открыть терминал в корне проекта.
2. Развернуть базу данных PostgreSQL с нужными параметрами, самый простой способ - запустить БД в докере командой:
```bash
docker compose up -d
```
2. Посмотреть список доступных команд:

```bash
ant help
```

3. Выполнить полную сборку и локальное развертывание:

```bash
ant full-build
```

В рамках этой команды выполняется следующая последовательность:

- создается директория `build/`, если она отсутствует;
- останавливается ранее запущенный локальный экземпляр приложения, если он существует;
- база данных пересоздается и инициализируется тестовыми/начальными данными через `db-reset`;
- с помощью Gradle собирается исполняемый JAR (`clean bootJar`);
- приложение запускается локально на порту `8080`;
- выполняется ожидание готовности приложения по адресу `http://localhost:8080/login`.

4. После завершения сборки открыть приложение в браузере:

- `http://localhost:8080/`
- `http://localhost:8080/login`

#### Остановка локального приложения

```bash
ant undeploy-local
```

### 6.4 Запуск тестов

#### DAO / unit-тесты

```bash
ant test
```

#### DAO / unit-тесты с отчетом покрытия

```bash
ant test-report
```

HTML-отчет JaCoCo генерируется по пути:

`build/reports/jacoco/test/html/index.html`

#### Selenium-системные тесты

```bash
ant system-test
```

Для запуска системных тестов с последующей остановкой локального приложения:

```bash
ant system-test-stop
```
