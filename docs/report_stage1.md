Отчет по 1 этапу: Интернет-магазин бытовой техники

Проект: Система учета данных о товарах и заказах
СУБД: PostgreSQL
Основные сущности: товары, клиенты, заказы

1. Сценарии использования (Use Cases)

UC-1. Просмотр каталога товаров

Цель: получить список доступных товаров.
Участники: гость/клиент.
Предусловия: товары есть в БД.
Основной поток:

1. Пользователь открывает страницу “Каталог товаров”.
2. Система отображает список товаров с основными полями (название, вид, производитель, цена, наличие).
3. Пользователь может перейти в карточку товара.

Страницы: Каталог товаров → Карточка товара.

UC-2. Фильтрация товаров по виду/производителю/характеристикам

Цель: отобрать товары по заданным условиям.
Участники: гость/клиент.
Основной поток:

1. Пользователь открывает “Каталог товаров”.
2. Выбирает фильтр по виду товара (например, “Телевизоры”) и/или производителю (например, “Samsung”).
3. При необходимости задает фильтр по характеристике (ключ/значение), например: resolution = 3840x2160.
4. Система показывает только товары, удовлетворяющие условиям.

Страницы: Каталог товаров.

UC-3. Просмотр карточки товара

Цель: увидеть полные данные товара: цена, наличие, характеристики.
Участники: гость/клиент.
Основной поток:

1. Пользователь в каталоге выбирает товар.
2. Система открывает карточку товара.
3. Система показывает: описание, цену, остаток, производителя и характеристики.

Страницы: Карточка товара.

UC-4. Оформление заказа

Цель: создать заказ с выбранными товарами и параметрами доставки.
Участники: клиент.
Предусловия: у товаров есть достаточный остаток.
Основной поток:

1. Пользователь открывает страницу “Оформление заказа”.
2. Вводит/выбирает данные клиента (ФИО, телефон, email, адрес).
3. Выбирает товары и количество по каждой позиции.
4. Вводит условия доставки (адрес, временное окно).
5. Система проверяет наличие товара на складе.
6. Система создает заказ со статусом processing (“в обработке”).
7. Система создает позиции заказа и фиксирует цену позиции (unit_price).
8. Система рассчитывает и сохраняет общую сумму заказа (total_amount).

* Если товара недостаточно на складе, заказ не создается, выводится сообщение об ошибке.

Страницы: Оформление заказа → Статус заказа.

UC-5. Проверка статуса заказа

Цель: узнать текущий статус заказа и его состав.
Участники: клиент.
Основной поток:

1. Пользователь открывает страницу “Статус заказа” и указывает номер заказа (или переходит по ссылке).
2. Система показывает статус (processing, packed, delivered), состав заказа и сумму.

Страницы: Статус заказа.

UC-6. Управление клиентом (добавление/редактирование/удаление)

Цель: поддерживать актуальные данные клиентов.
Участники: администратор/оператор (или клиент при редактировании профиля).
Основной поток:

1. Открыть страницу “Клиенты”.
2. Создать нового клиента / выбрать существующего.
3. Отредактировать данные / удалить клиента.
4. Система сохраняет изменения в БД.

Страницы: Список клиентов → Профиль клиента.

UC-7. Управление товарами (добавление/редактирование/удаление)

Цель: поддерживать каталог товаров и характеристики.
Участники: администратор.
Основной поток:

1. Открыть страницу “Управление товарами”.
2. Добавить новый товар: вид, производитель, название, цена, остаток, описание.
3. Добавить/изменить характеристики товара (набор key/value).
4. Отредактировать данные / удалить товар.
5. Система сохраняет изменения.

Страницы: Управление товарами.

2. Перечень страниц приложения и модель содержимого

P-1. Каталог товаров (/products)

Данные на странице:

* список товаров: product.name, product.price, product.stock_qty
* вид: product_type.name
* производитель: manufacturer.name, manufacturer.assembly_country

Фильтры:

* по виду товара (product_type)
* по производителю (manufacturer)
* по характеристике (product_attribute.attr_key + product_attribute.attr_value)

Действия:

* применить фильтры
* перейти в карточку товара

P-2. Карточка товара (/products/{id})

Данные:

* товар: name, description, price, stock_qty
* вид: product_type.name
* производитель: manufacturer.name, manufacturer.assembly_country
* характеристики: список product_attribute(attr_key, attr_value)

Действия:

* перейти к оформлению заказа (или добавить в заказ)

P-3. Оформление заказа (/orders/new)

Данные/ввод:

* клиент: ФИО, телефон, email, адрес
* доставка: адрес, временное окно
* позиции заказа: товар + количество
* итого: расчетная сумма заказа

Действия:

* создать заказ

P-4. Статус заказа (/orders/{id})

Данные:

* заказ: id, created_at, status, delivery_address, delivery_time_window, total_amount
* позиции: order_item.qty, order_item.unit_price, order_item.line_total, + данные товара

Действия:

* обновить/проверить статус

P-5. Список клиентов (/customers)

Данные:

* список клиентов: full_name, phone, email

Действия:

* открыть профиль клиента
* создать нового клиента
* удалить клиента

P-6. Профиль клиента (/customers/{id})

Данные:

* full_name, phone, email, address
* список заказов клиента: orders.created_at, orders.status, orders.total_amount

Действия:

* редактировать данные клиента

P-7. Управление товарами (/admin/products)

Данные:

* список товаров + основные поля
* формы добавления/редактирования
* блок управления характеристиками товара

Действия:

* добавить/редактировать/удалить товар
* добавить/редактировать/удалить характеристику

3. Схема навигации

* Каталог товаров → Карточка товара
* Карточка товара → Оформление заказа
* Оформление заказа → Статус заказа
* Список клиентов → Профиль клиента
* Профиль клиента → Статус заказа (по выбранному заказу)
* (Админ) Управление товарами → Каталог товаров (для проверки отображения)

4. Схема базы данных и соответствие UI ↔ БД

4.1 Таблицы и поля

product_type

* id (PK)
* name (уникальное название вида товара)

manufacturer

* id (PK)
* name
* assembly_country
* уникальность: (name, assembly_country)

product

* id (PK)
* type_id (FK → product_type.id)
* manufacturer_id (FK → manufacturer.id)
* name, description
* price
* stock_qty
* created_at, updated_at

product_attribute

* id (PK)
* product_id (FK → product.id, ON DELETE CASCADE)
* attr_key, attr_value (характеристики key/value)

customer

* id (PK)
* full_name
* phone, email (email уникален, допускается NULL)
* address
* created_at

orders

* id (PK)
* customer_id (FK → customer.id)
* created_at
* status (ENUM order_status: processing, packed, delivered)
* delivery_address
* delivery_time_window
* total_amount

order_item

* id (PK)
* order_id (FK → orders.id, ON DELETE CASCADE)
* product_id (FK → product.id)
* qty
* unit_price
* line_total (вычисляемое поле qty * unit_price)

4.2 Связи между таблицами

* product_type (1) → (N) product
* manufacturer (1) → (N) product
* product (1) → (N) product_attribute
* customer (1) → (N) orders
* orders (1) → (N) order_item
* product (1) → (N) order_item

4.3 Отображение данных БД на страницы UI

* Каталог товаров: product + product_type + manufacturer
* Фильтры по характеристикам: product_attribute
* Карточка товара: product + product_attribute + manufacturer + product_type
* Оформление заказа: customer + orders + order_item + product
* Статус заказа: orders + order_item + product
* Клиенты: customer + связанные orders

5. Скрипты и сборка

* create.sql — создание таблиц и индексов
* init.sql — примерное заполнение таблиц
  * Из корня проекта:
  ant db-create (создание таблиц в БД)
  ant db-init (заполнение таблиц начальными данными)
  ant db-show (показать данные в БД)
  ant db-clean (очистить БД)
  ant db-reset (пересоздание БД и заполнение ее начальными данными)
